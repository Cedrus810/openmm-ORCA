## T04 — checkpoint、运行状态与续跑

- `examples/enzyme_qmmm.py`：`--checkpoint-interval`（默认 100，须为 DCD 间隔 10 的倍数），写 OpenMM checkpoint（`.chk`）与 State XML，经 `run.json` 原子提交（记录状态、各次尝试、`steps.csv` 字节数与 SHA-256、平台与 OpenMM 版本）。完成时写 `final_state.xml`、`final.pdb`。`--resume checkpoint|state`、`--archive-existing`、输出目录 flock。
- 续跑校验运行身份：起始 State、拓扑、MM System 哈希、QM 设置、反应键、`min_iterations`、`QMMM_RECIPE`。nprocs 与平台按尝试记录，不属于身份。
- QM/MM Langevin 积分器现显式设种子（`integrator_seed` 2029；State 续跑用 seed + 尝试序号 − 1）。

探针（OpenMM 8.5.2，Reference）：带 PythonForce 的 Context checkpoint 在新 Context 中加载后，Verlet 与 Langevin 继续积分均与不中断运行逐位一致。前提是 QM 后端无状态；原 `FakeBackend` 的 r0 取自首次调用，重建后基准改变（差 4.5e-5 nm），测试中的 fake 改为固定 r0。

ORCA 的 last-good `.gbw` 位于旧 backend 的临时 scratch，不跨进程保留；续跑首步为 fresh SCF，与不中断运行只在 SCF 收敛精度内一致。ORCA 与 CUDA 上的续跑尚未实测（T07）。

## T05 — 版本与打包

发现：源码 `__version__` 与 `pyproject.toml` 为 0.4.0；`openmm_dev` 中的 editable 安装为 0.0.1（`pip show`，仓库外 `importlib.metadata`）；在仓库目录内 `importlib.metadata` 读到仓库根目录过期的 `openmm_orca.egg-info`，报告 0.2.0。

修改：
- `pyproject.toml` 版本改为 `dynamic`，取自 `openmmorca.__version__`，只保留一个来源。
- `build-system` 下限由 `setuptools>=64` 改为 `>=77`：PEP 639 的字符串 `license = "MIT"` 需要 77 及以上。
- 新增 `tests/test_packaging.py`：检查版本单一来源；已安装元数据与导入包版本不一致时失败（刷新前实测报 `'0.2.0' == '0.4.0'` 失败）。

wheel 检查：从源码副本（不在仓库内写 `build/`）构建 `openmm_orca-0.4.0-py3-none-any.whl`。METADATA 版本 0.4.0、`License-Expression: MIT`、依赖 `openmm>=8.5`、`orca-pi>=2.0`、`numpy`；包含 `openmmorca` 全部 21 个模块，不含 tests/examples。

干净环境：不继承 site-packages 的新 venv（Python 3.12.13），从 PyPI 安装 wheel 及依赖：OpenMM 8.6.1、orca-pi 2.0.0、numpy 2.5.3、pytest 9.1.1。在不含 `openmmorca` 源码的目录运行 tests/ 与 examples/ 副本，确认导入来自 venv 且版本一致。

```bash
env -u OPI_ORCA venv/bin/python -m pytest -m 'not orca and not slow' -q
```

首次结果 3 failed / 176 passed：均为 T04 新测试，`TimedFake` 键力常数 1000 kJ/mol/nm² 过软，30 步内键偏离接近 20% 冒烟门槛，OpenMM 8.6.1 的随机序列达 23.4%。改为 4e5（接近 O–H）后最大偏离 ≤ 3.2%，**179 passed, 37 deselected**。这是测试设计问题，不是包或 OpenMM 8.6.1 的缺陷。ORCA 测试未在该 venv 中运行。
